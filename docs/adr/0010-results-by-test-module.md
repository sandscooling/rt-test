# Store and rate results by test module

Status: accepted

A stored run answers for a whole Vitest workspace: the run stored last for a workspace gives every test of it its state, and one input fingerprint of the workspace rates them all (ADR-0007 names the same grain for defect evidence). So a run of part of a workspace cannot be stored without displacing the rest, an interrupted run keeps nothing, and one edit stales every result and every defect's evidence in its workspace. Measured on Fleet Cooling on 2026-10-02 (Vitest 4.1.11, Windows 11, a Ryzen 7 8700F): every workspace there depends on its Convex workspace, so one edit in it reran all 14,994 tests, the Convex answer 3 min 41 s after the save and everything 7 min 36 s after it, restarted by every save, where its agents get an answer in 1.5 to 4.3 s from the one to five test files they name themselves.

The test module is the unit. A run covers a list of one workspace's test modules and is stored whole. Each test's state comes from the latest stored run that covered its test module, and that module's result is bound to an input fingerprint of the module's own inputs: its workspace's shared inputs and the files the module can load (ADR-0011). A stored run replaces the earlier results of exactly the modules it covers. No later run covers a test module that left its workspace, so a stored discovery removes the results of the modules its workspaces no longer list. A module is due when its latest result is not bound to its current fingerprint, and a workspace is due while any of its modules is. Defect evidence is bound to the fingerprint of its test's module, so an edit stales the evidence of the modules it reaches and of no other.

Duplicate execution (NFR1) is measured where every result passes: the write that replaces a module's result compares the fingerprint it stores with the one it replaces, and the log counts each module stored again under the same one. A selection miss (NFR2) is measured as before, the daemon's current results against a full run of plain Vitest over the same input snapshot, over an edit corpus that gains the file-level cases.

Rejected: keeping the workspace as the unit and only ordering its run, which leaves every edit's cost at its workspace's run and an interrupted run with nothing. Rejected: the single test as the unit, since Vitest loads and runs a module whole and a test's inputs cannot be told apart from its module's.
