# Decide detection from Vitest's task facts, confirmed per Vitest version by canaries

Status: accepted

ADR-0003 decides each verdict from run facts rather than message text. This records which facts, how they decide, and how RT Test knows it reads them correctly on the Vitest a consumer installed.

The falsifier records, for each experiment and for the intended test found by its stable identity: its state; the kind of each of its errors, which is an assertion when Vitest serializes it as an `AssertionError` or as a matcher failure it marks with the `JestExtendError` constructor and an assertion name (the form `expect.extend` matchers such as jest-dom's take), or when its name is one the consumer declares in the `assertionErrors` member of `rt-test.json`, and otherwise another kind; the hook states Vitest records on the test's result; the module and suite errors; the run's unhandled errors; whether the mutated site executed during that test (reach); and the intended test's result in the baseline and the restored baseline.

Reach comes from a reach probe the mutation's own transform inserts. The transform parses the module before and after the mutation with the parser the dependency build uses, finds the smallest pair of nodes standing in the same place that hold the whole change, and places a call to a recorder only where the call firing means the changed code began executing. A probe may stand on the smallest construct that always runs the change once it starts, barring a throw inside that construct; it never stands across a conditional or later-run step (a right operand of `&&`, `||` or `??`, a branch, a loop's body, a `case`, a `catch`, a function's body or its parameters, a default value, a class member, a link to the right of an optional chain's `?.`). Code that was only removed is placed by the unmutated text: the probe stands where execution reaches the place the removed code stood. The call is placed around an expression whose meaning a comma expression keeps; as a statement at the changed place in a statement list, which is where removed and added statements are probed; at the head of a function's body when the function or its parameters changed; or, for a dropped right operand of `&&`, `||` or `??`, as an inline function that takes the kept operand's value once, fires only when the dropped operand would have been evaluated, and returns the value unchanged. A changed part that takes no call itself (a callee, a property name, template text, an object literal's property, a declarator, an assignment target) is probed through the nearest enclosing construct that always evaluates it. A setup file RT Test places first in every project marks the test Vitest reports as running when the probe fires, through the test's metadata, which Vitest returns to the main process. Code that runs while the module loads marks every test of that test file, since each can read what it set, and the setup file clears that mark for each file. Where no probe can be placed (any position the placement rules do not admit, among them a type, an import, a function's name alone, a removed `else`, `case`, `catch` or function declaration, an added `case` or `catch`, a change to the right of an optional chain's `?.` that takes no call itself, JSX text, attributes and element names, a change of white space or comments only, or a module that does not parse before or after the mutation), the experiment is decided before any run: it does not run, and its record names the position.

An experiment would be detected when the baseline and the restored baseline passed the intended test, the mutated site executed during it, and it failed with every hook it ran ending in pass, at least one error and every error an assertion error, and no module, suite or unhandled error. A would-be detection is run once more, at once, as a confirming run in the same instance, and is detected only when that run meets the same conditions and the run the job starts next records no unhandled error; otherwise it is unclear, naming the instability. It survived when the intended test passed after the site executed. It is an invalid experiment when either baseline did not pass the intended test, did not end cleanly, or recorded an unhandled error that names the intended test's module or names none; when a hook did not end in pass, a module or suite error was recorded, the site did not execute during the intended test or its reach is unknown, or the intended test did not run. It is unclear when the intended test failed with an error that is not an assertion, as a thrown `TypeError` or a timeout is, or beside an unhandled error. An experiment whose job did not finish its runs has no verdict. Anchor missing and an invalid definition are decided before any run.

Observed on 2026-09-30 on Vitest 4.1.11 and 5.0.1: a `beforeEach` that throws leaves that hook's state `run`, never `fail`; a custom matcher's failure serializes with the name `Error`, the `JestExtendError` constructor and its assertion name; a timeout and a `TypeError` in the body carry no assertion marker. A probe call recording through `TestRunner.getCurrentTest()`, which `vitest` exports on both lines, marked the test that executed the site and left unmarked a test in the same file that failed an assertion without executing it; a site run while the module loaded marked every test of the file through the setup file's `beforeEach`, whose own state was `pass`.

These facts are Vitest's internals, and a release that stopped recording hook states would credit an `expect` failing in a `beforeEach` as a detection. So RT Test ships canary fixtures, each failing on purpose in one known way, which its own suite checks on both supported Vitest lines. Before a workspace's first falsification on a Vitest version, the daemon runs those canaries under that workspace's Vitest from its state directory and keeps the result per Vitest and falsifier version; a version whose reading disagrees with any canary is refused falsification, naming the version and the canary.

Rejected: matching message text, which ADR-0003 rejects. Rejected: reach by module, whether the mutated module loaded, which credits a test that fails an assertion by chance while the mutated site never runs. Rejected: reach by line through V8 coverage, which costs every experiment a coverage pass and still cannot tell which test executed a line, where the probe answers that exactly at the cost of one call. Rejected: a confirming run alone, without the probe, which only narrows the chance of crediting a site that never ran. Rejected: the failure phase from stack frames, which are paths and text. Rejected: trusting these facts on a version no canary has confirmed.

Known limits: a test that executes the mutated site and fails an assertion by chance in both the experiment and its confirming run reads as detected, and a site run while its module loads counts for every test of that file. Falsification runs every test file isolated, whatever the workspace configures, so a module's load-time code runs again for each test file. A site reached only in an `afterAll` fires after the test's result is final, so it reads as not reached and the experiment is invalid. A site reached while tests run concurrently reads unknown. A probe fires when its construct starts, so a throw inside that construct before the changed code leaves the change un-run with the probe fired. A mutation that changes several statements is probed for the first of them. Code a finished or timed-out test left running can be credited to another running test, and a mark carries across a test's retries. An `expect.assertions` count failure carries no assertion marker and reads as unclear. A Testing Library query error reads as unclear unless the consumer declares its name. A snapshot matcher's mismatch carries no assertion marker and reads as unclear. A retried test keeps every attempt's errors, so every error must be an assertion, and an `expect.soft` failure followed by a throw reads as unclear. A defect on an `it.fails` test reads as unclear. A baseline that passed only on a retry reads as a pass. When the experiment that runs next leaks an unhandled error, the detection before it reads as unclear. A module holding a suite whose `beforeAll` always fails has no detection. An assertion that fails in a fixture's setup or in an `onTestFinished` callback has no hook state and reads as a failure in the test's body.
