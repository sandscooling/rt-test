# Decide detection from Vitest's task facts, confirmed per Vitest version by canaries

Status: accepted

ADR-0003 decides each verdict from run facts rather than message text. This records which facts, how they decide, and how RT Test knows it reads them correctly on the Vitest a consumer installed.

The falsifier records, for each experiment and for the intended test found by its stable identity: its state; the kind of each of its errors, which is an assertion when Vitest serializes it as an `AssertionError` or as a matcher failure it marks with the `JestExtendError` constructor and an assertion name (the form `expect.extend` matchers such as jest-dom's take), or when its name is one the consumer declares in `rt-test.json`, and otherwise another kind; the hook states Vitest records on the test's result; the module and suite errors; the run's unhandled errors; whether the mutated site executed during that test (reach); and the intended test's result in the baseline and the restored baseline.

Reach comes from a reach probe the mutation's own transform inserts. The transform parses the mutated module with the parser the dependency build uses and places a call to a recorder at the smallest syntax node enclosing the changed text, only where the call firing means the changed code began executing: around an expression whose meaning a comma expression keeps, or before a statement in a statement list. A setup file RT Test places first in every project marks the test Vitest reports as running when the probe fires, through the test's metadata, which Vitest returns to the main process. Code that runs while the module loads marks every test of that test file, since each can read what it set, and the setup file clears that mark for each file. Where no probe can be placed, because the change sits in a callee, an assignment target, a type or any other position the call would alter, or the mutated module does not parse, reach is unknown and the experiment is invalid.

An experiment would be detected when the baseline and the restored baseline passed the intended test, the mutated site executed during it, and it failed with every hook it ran ending in pass, at least one assertion error, and no module, suite or unhandled error. A would-be detection is run once more, as a confirming run in the same instance, and is detected only when that run meets the same conditions; otherwise it is unclear, naming the instability. It survived when the intended test passed after the site executed. It is an invalid experiment when either baseline did not pass, a hook did not end in pass, a module or suite error was recorded, the site did not execute during the intended test or its reach is unknown, or the intended test did not run. It is unclear when the intended test failed in its body with no assertion error, as a thrown `TypeError` or a timeout does, or beside an unhandled error. Anchor missing and an invalid definition are decided before any run.

Observed on 2026-09-30 on Vitest 4.1.11 and 5.0.1: a `beforeEach` that throws leaves that hook's state `run`, never `fail`; a custom matcher's failure serializes with the name `Error`, the `JestExtendError` constructor and its assertion name; a timeout and a `TypeError` in the body carry no assertion marker. A probe call recording through `TestRunner.getCurrentTest()`, which `vitest` exports on both lines, marked the test that executed the site and left unmarked a test in the same file that failed an assertion without executing it; a site run while the module loaded marked every test of the file through the setup file's `beforeEach`, whose own state was `pass`.

These facts are Vitest's internals, and a release that stopped recording hook states would credit an `expect` failing in a `beforeEach` as a detection. So RT Test ships canary fixtures, each failing on purpose in one known way, which its own suite checks on both supported Vitest lines. Before a workspace's first falsification on a Vitest version, the daemon runs those canaries under that workspace's Vitest from its state directory and keeps the result per Vitest and falsifier version; a version whose reading disagrees with any canary is refused falsification, naming the version and the canary.

Rejected: matching message text, which ADR-0003 rejects. Rejected: reach by module, whether the mutated module loaded, which credits a test that fails an assertion by chance while the mutated site never runs. Rejected: reach by line through V8 coverage, which costs every experiment a coverage pass and still cannot tell which test executed a line, where the probe answers that exactly at the cost of one call. Rejected: a confirming run alone, without the probe, which only narrows the chance of crediting a site that never ran. Rejected: the failure phase from stack frames, which are paths and text. Rejected: trusting these facts on a version no canary has confirmed.

Known limits: a test that executes the mutated site and fails an assertion by chance in both the experiment and its confirming run reads as detected, and a site run while its module loads counts for every test of that file. Under `isolate: false`, a module a previous test file loaded runs no load-time code again, so its load-time site reads as not reached and the experiment is invalid rather than detected. An `expect.assertions` count failure carries no assertion marker and reads as unclear. A Testing Library query error reads as unclear unless the consumer declares its name.
