# Decide detection from Vitest's task facts, confirmed per Vitest version by canaries

Status: accepted

ADR-0003 decides each verdict from run facts rather than message text. This records which facts, how they decide, and how RT Test knows it reads them correctly on the Vitest a consumer installed.

The falsifier records, for each experiment and for the intended test found by its stable identity: its state; the kind of each of its errors, which is an assertion when Vitest serializes it as an `AssertionError` or as a matcher failure it marks with the `JestExtendError` constructor and an assertion name (the form `expect.extend` matchers such as jest-dom's take), or when its name is one the consumer declares in the `assertionErrors` member of `rt-test.json`, and otherwise another kind; the hook states Vitest records on the test's result; the module and suite errors; the run's unhandled errors; whether that test reached the step that holds the mutation (reach); and the intended test's result in the baseline and the restored baseline.

Reach comes from a reach probe the mutation's own transform inserts, and it is reach of a step: the probe firing means execution reached the step that holds the change, and says nothing of which part of that step ran. A step is the innermost statement around the change, or the head of a function's body when the change sits in that function outside every statement of its body (its parameters, its name, an arrow's expression body); a class field's initializer is probed as such a body is. The transform parses the mutated module with the parser the dependency build uses and writes a call to a recorder as a statement just before the step's statement: in a statement list after any directive prologue, ending the list when the change follows its last statement, and with a statement that stands alone as a branch or a loop's body made a block that starts with the call. An expression body and a field's initializer take the call as the first member of a comma expression. The call is never placed around a part of a statement, so the rule holds no table of which parts of which construct always run, and it stands inside every function that holds the change, so it never fires where that function is defined. Text that was only removed has no extent in the mutated module, so the step that held it is found in the module's text before the mutation, and the probe's step holds the written text and the start of that step. A setup file RT Test places first in every project marks the test Vitest reports as running when the probe fires, through the test's metadata, which Vitest returns to the main process. Code that runs while the module loads marks every test of that test file, since each can read what it set, and the setup file clears that mark for each file. Where no probe can be placed (inside an ambient declaration, in a module the mutation leaves with no statement, where the parser rejects the module with the call written in, or in a module that does not parse after the mutation), the experiment is decided before any run: it does not run, and its record names the position.

An experiment would be detected when the baseline and the restored baseline passed the intended test, its run ended cleanly, the intended test reached the step that holds the mutation, and that test failed holding a recorded `beforeEach` state with every hook state Vitest recorded on it `pass`, declaring no repeats, with at least one error and every error an assertion error, and with no module, suite or unhandled error in the run. A would-be detection is run once more, at once, as a confirming run in the same instance, and is detected only when that run meets the same conditions, the run the job starts next leaves a record that holds no unhandled error, and the job's own process recorded no unhandled error and closed the instance; otherwise it is unclear, naming the instability. It survived when the intended test passed after it reached that step. It is an invalid experiment for the first of these that holds: its change has no probe site; no test module holds its test; the baseline, and then the restored baseline, did not pass the intended test, did not end cleanly, or recorded an unhandled error that names the intended test's module or names none; its own run did not end cleanly; a module or suite error was recorded; the intended test did not run; a hook did not end in pass or the test holds no `beforeEach` state; the test failed and declares repeats; or the intended test did not reach that step or its reach is unknown. It is unclear when the intended test failed with no error or with an error that is not an assertion, as a thrown `TypeError` or a timeout is, or beside an unhandled error. An experiment the job did not finish has no verdict: its own run, its confirming run or a baseline left no record, or the job could not read its mutation's file or find its anchor exactly once when it started. Anchor missing and an invalid definition are decided before any run.

Observed on 2026-09-30 on Vitest 4.1.11 and 5.0.1: a `beforeEach` that throws leaves that hook's state `run`, never `fail`; a custom matcher's failure serializes with the name `Error`, the `JestExtendError` constructor and its assertion name; a timeout and a `TypeError` in the body carry no assertion marker. A probe call recording through `TestRunner.getCurrentTest()`, which `vitest` exports on both lines, marked the test that executed the site and left unmarked a test in the same file that failed an assertion without executing it; a site run while the module loaded marked every test of the file through the setup file's `beforeEach`, whose own state was `pass`.

These facts are Vitest's internals: a release that recorded a hook's state differently would credit an `expect` failing in a `beforeEach` as a detection, and one that stopped recording hook states would leave every experiment invalid. So RT Test ships canary fixtures, each failing on purpose in one known way, which its own suite checks on both supported Vitest lines. Before a workspace's first falsification on a Vitest version, the daemon runs those canaries under that workspace's Vitest from its state directory and keeps the result per Vitest and falsifier version; a version whose reading disagrees with any canary is refused falsification, naming the version and the canary.

Rejected: matching message text, which ADR-0003 rejects. Rejected: reach by module, whether the mutated module loaded, which credits a test that fails an assertion by chance while the mutated step never runs. Rejected: reach of the changed code itself, with the call placed around the smallest construct that always runs the change, which needs a table of which parts of each construct always run and a comparison of the module's parse before and after the mutation; a codebase writes shapes such a table has not met, and each shape it misjudges fires the call early, where reach of a step is that coarse by one rule and says so. Rejected: reach by line through V8 coverage, which costs every experiment a coverage pass and still cannot tell which test executed a line, where the probe answers that exactly at the cost of one call. Rejected: a confirming run alone, without the probe, which only narrows the chance of crediting a site that never ran. Rejected: the failure phase from stack frames, which are paths and text. Rejected: trusting these facts on a version no canary has confirmed.

Known limits: a test that reaches the step and fails an assertion by chance in both the experiment and its confirming run reads as detected, and a step that runs while its module loads counts for every test of that file. Reach is of the step, so a test that reaches the step without evaluating its changed part, as one that stops at `a` in `a && b` with `b` changed, reads as having reached it; it then reads survived unless it fails by chance in both runs. A construct the rule does not name that runs later than where it is written is probed where it is defined, so a test that never ran the change can read as having reached it; the rule names a function and a class field's initializer. Falsification runs every test file isolated, whatever the workspace configures, so a module's load-time code runs again for each test file. A step reached only in an `afterAll` fires after the test's result is final, so it reads as not reached and the experiment is invalid. A step reached while tests run concurrently reads unknown. A mutation that changes several statements is probed before the first of them. A changed parameter default or pattern that throws ends the call before the probe at the body's head, and a parameter's decorator runs when its class is defined, so each reads as not reached. A class decorated before `export` has no probe site for a change in its decorators or its members' names, since no statement can stand between a decorator and `export`. A module that binds a name `globalThis` of its own makes the probe throw or record nothing. A class field whose value is an unnamed class loses the name the field gives that class when the change sits in the class outside its methods. A mutation of types alone, outside an ambient declaration, is run and reads survived. A probe before `super()` in a constructor is confirmed through Vite 8's TypeScript transform and through no earlier one. Code a finished or timed-out test left running can be credited to another running test, and a mark carries across a test's retries. An `expect.assertions` count failure carries no assertion marker and reads as unclear. A Testing Library query error reads as unclear unless the consumer declares its name. A snapshot matcher's mismatch carries no assertion marker and reads as unclear. A retried test keeps every attempt's errors, so every error must be an assertion, and an `expect.soft` failure followed by a throw reads as unclear. A defect on an `it.fails` test reads as unclear. A baseline that passed only on a retry reads as a pass. A detection reads as unclear when the run the job starts next records any unhandled error, the restored baseline included, even one that names another test module, so a test module of the job that leaks in every run leaves the job's last detection unclear. A module holding a suite whose `beforeAll` always fails has no detection. An assertion that fails outside the test's body where Vitest records no failed hook state (a fixture's setup or teardown, a cleanup a `beforeEach` returns, an `aroundEach` hook, an `onTestFinished` callback, an `expect.soft` in a `beforeEach` or `afterEach`) reads as a failure in the test's body and can read detected. A defect on a test that declares repeats, its own, a suite's or the project's, can read survived but never detected: a repeated test that failed reads as an invalid experiment, since the hook states it holds are its last repeat's alone. A test that fails under the mutation and passes on a retry reads as survived. A mutated module that throws while it loads leaves its test module collected with a module error, and reads as an invalid experiment. A test that fails before it reaches a file snapshot assertion leaves that snapshot unchecked, which Vitest reports as a module error while no snapshot may be written, so every experiment whose test is in that module reads as invalid in that run. An `AssertionError` the code under test raises itself, as an invariant checked with `node:assert` does, reads as the test's assertion, so a defect can read detected by a test whose own assertions do not check it.
