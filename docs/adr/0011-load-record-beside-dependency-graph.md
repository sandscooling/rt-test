# Select by what each test module loaded, beside a kept dependency graph

Status: accepted

Selecting below the workspace needs to know which test modules an edit can reach. Three sources were measured on 2026-10-02 over a consumer written for it (3,365 source files, Vitest 4.1.11, Node 24.19.0, Windows 11, a Ryzen 7 8700F with 16 logical CPUs), one of whose workspaces reaches its code as a Convex package is reached: a lazy `import.meta.glob` registry, a generated `api` object, a barrel, and a dispatch whose target is a variable. For a module that 3 of 31 test modules really load, a graph of static imports selected 31; TypeScript's import graph 30, or none with type-only imports left out, and its find-references none; Vitest's related reading 31 and its public import record none; and the list of modules each test module's own worker executed selected the 3. Fleet Cooling's `scripts/test-blast-radius.mjs`, once planned as a Convex adapter, never selects under 263 of its 583 Convex test files, which take 172.7 s of the suite's 191 s.

Two sources are kept, each answering what the other cannot.

**The dependency graph** holds each source file's imports: a file-to-file edge where a specifier is a path, an edge to a whole package workspace where it is a package name, an alias or a tsconfig path, and the pattern itself where it is a glob. The daemon scans it once in its life and afterwards re-reads only the files a change names, in memory (measured: 2.0 s to scan the 3,365 files and 0.6 ms for one edited file, where every save pays two whole-tree builds today, 4.6 s and 4.9 s of the 13.5 s Fleet Cooling waits before a run starts). It stays coarse wherever a name is not a path, because it never narrows a selection by itself: its work is to miss nothing.

**The load record** is the list of consumer files a test module's worker executed in the run that produced its stored result, reported by a setup file RT Test places first and stored with that result.

One rule decides a test module's inputs: they are its workspace's shared inputs and its own files, its own files come from its load record where the record can vouch and from the graph where the graph can, and where neither can vouch the module keeps every input of its workspace, as at workspace granularity. The shared inputs are the workspace's config, setup and env files with every file the config or a setup file reaches by the graph, since a config runs outside every test's worker, manifests and lockfiles, every input that is not a source module, and every source file the graph cannot read; a change to one selects every test module of the workspace. Its own files are:

- the files in its load record, when the record is usable, with every file of a package workspace the module reaches by name while the record holds none of that workspace's files, since a package the worker loads outside Vitest's module runner leaves no file in the record;
- else every file the graph says it can reach, when no file among them holds a module path computed at run time;
- else every input of its workspace.

A load record is usable only when all of these hold: the module's stored result came from a completed run in which the module ran, with each test module isolated from the others; the record holds the test module itself; the run's Vitest install has a confirmed reading of the record canaries in this daemon's life; and neither the test module nor any consumer file in the record imports one of Node's own built-in modules that read files or start code by path, a fixed list taken from Node (`fs`, `child_process`, `worker_threads`), since the record sees only modules executed in the test's own worker. A module that imports one keeps every input of its workspace, so nothing it reads can read wrongly current and it gains nothing. No list of third-party libraries is kept.

The graph answers beside the record for what no record can have seen. A new file reaches every test module whose inputs hold a file that names it, by an import that now resolves to it or a glob pattern that matches it. A deleted or renamed file reaches the modules whose inputs held it. A content edit of an existing file reaches the modules whose inputs hold it and no other: a module that did not execute the file runs the same code as before, whatever the file now imports.

That is why the record may exclude, and never alone. A current result's record comes from the very run that produced the result, and the result stays current only while no file in the record and no shared input has changed, so the module would load the same files again. A module whose result is not current is run, whatever its record says.

The record is read from Vitest's worker state (`__vitest_worker__.moduleExecutionInfo`), which is not public API. The canary set gains fixtures whose test modules load a known list each way (a static import, an import by variable inside a test, a lazy glob registry, a barrel, a module mocked by a factory and never loaded), and a canary reading compares each record with its list exactly. Under a Vitest install whose reading disagrees or gives none, as after an upgrade to a Vitest whose worker state reads differently, no record narrows a selection or orders a run (ADR-0012): its workspaces select by the graph, and every answer says so, as a workspace refused by ADR-0008's gate is listed.

Known limits. A test module whose loads differ between two runs over the same inputs. A file read as data, or code started by path, through a library and not through a Node built-in. A file most test modules load selects them all by any source: 79 of the 175 Convex source files in Fleet Cooling's last 100 commits reach 263 or more of its test files by real static edges. A new file that matches a registry's glob selects every test module that loads the registry. A consumer whose own code reads files or starts processes, as this repository's does, narrows little.

Rejected: static imports alone (31 of 31 above). Rejected: a language server (30 or none, 360 to 540 MB and 2.7 to 5.4 s to start, and a TypeScript below 7 in the consumer). Rejected: porting the blast-radius script as a Convex adapter, for the 263 above; nothing Convex-specific enters the product, and an adapter returns only for a dependency neither source sees. Rejected: Vitest's public import record, which is taken at collection and misses what a test loads while it runs. Rejected: recording file reads by patching `fs` in the worker, which changes the consumer's runtime.
